# ML Pipeline — Dataset to Deployment

## Flow

```
 ml/data/raw/telco_churn.csv
            │
            ▼
 ┌────────────────────────┐
 │ preprocess.py           │  schema check (expected columns, dtypes, null thresholds)
 │                         │  imputation, stratified train/test split
 └───────────┬────────────┘
             ▼
 ┌────────────────────────┐
 │ features.py             │  ColumnTransformer: numeric passthrough/scaling +
 │                         │  OneHotEncoder(handle_unknown="ignore")
 └───────────┬────────────┘
             ▼
 ┌────────────────────────┐
 │ train.py                │  RandomForestClassifier, mlflow.start_run()
 │                         │  log_param(hyperparams) / log_metric(f1_score, roc_auc)
 │                         │  log_model (sklearn + pyfunc wrapper)
 │                         │  register_model("churn-model")
 └───────────┬────────────┘
             ▼
   MLflow Registry: version N → Staging          (automatic)
             │
             ▼
 ┌────────────────────────┐
 │ evaluate.py             │  loads the Staging version and the current Production
 │                         │  version, scores both on the held-out test set,
 │                         │  fails if F1 regresses by more than 1%
 └───────────┬────────────┘
             ▼
      ╔═══════════════════════════════╗
      ║  MANUAL APPROVAL GATE          ║  Jenkins input step →
      ║  (Jenkins pipeline `input`)     ║  scripts/train-and-register.sh --promote
      ╚═══════════════┬═══════════════╝
                      ▼
   MLflow Registry: version N → Production
                      │
             ┌────────┴────────┐
             ▼                 ▼
 ┌────────────────────┐  ┌──────────────────────────────┐
 │ build.sh            │  │ deploy.sh                      │
 │ docker build         │  │ kubectl set image + rollout    │
 │ (code only, no model)│  │ restart deployment/fastapi     │
 └────────┬───────────┘  └───────────────┬──────────────┘
          └───────────────┬──────────────┘
                          ▼
             FastAPI pods restart → model_loader.py pulls
             models:/churn-model/Production at startup
                          │
                          ▼
                  POST /predict  → PostgreSQL predictions table
                                 → Prometheus /metrics
```

## Stage-to-file mapping

| Stage | File | Detail |
|---|---|---|
| Dataset | `ml/data/raw/telco_churn.csv` | ~7k synthetic Telco churn rows, generated by `ml/data/raw/generate_telco_churn.py` |
| Data validation | `ml/training/preprocess.py` | expected columns, dtypes, null thresholds |
| Preprocessing | `ml/training/preprocess.py` | imputation, stratified train/test split (`test_size: 0.2`, `random_state: 42`) |
| Feature engineering | `ml/training/features.py` | `build_preprocessor()` — numeric + one-hot categorical |
| Train | `ml/training/train.py` | `RandomForestClassifier`, hyperparameters from `ml/training/config.yml` |
| Track | `ml/training/train.py` | `mlflow.log_param`, `mlflow.log_metric("f1_score"/"roc_auc")` |
| Package | `ml/training/train.py` | `ChurnModelWrapper` (pyfunc) returns `prediction` + `probability` columns |
| Register | `ml/training/train.py` | `mlflow.register_model()` then transition to `Staging` |
| Evaluate | `ml/evaluation/evaluate.py` | Staging vs Production comparison, F1 regression tolerance |
| Promote | `scripts/train-and-register.sh --promote` | manual gate → `Production` |
| Build | `cicd/stages/build.sh` | `docker/fastapi/Dockerfile`, code only |
| Deploy | `cicd/stages/deploy.sh` | `kubectl set image` + `kubectl rollout restart` |
| Serve | `api/app/routers/predict.py` | `POST /predict` |
| Monitor | `api/app/metrics.py` + Prometheus | request rate, latency, prediction distribution |

## Model and features

- **Problem**: Telco customer churn, binary classification, tabular. No GPU needed.
- **Framework**: scikit-learn `RandomForestClassifier` (`n_estimators: 200`,
  `max_depth: 12`, `min_samples_split: 10`, `min_samples_leaf: 4`, `max_features: "sqrt"`,
  `class_weight: "balanced"`).
- **Target metrics**: F1 and ROC-AUC — churn is imbalanced, so accuracy is not a useful
  primary metric. `class_weight: "balanced"` is set for the same reason.
- **Numeric features**: `tenure`, `monthly_charges`.
- **Categorical features**: `gender`, `senior_citizen`, `partner`, `dependents`,
  `phone_service`, `multiple_lines`, `internet_service`, `online_security`, `online_backup`,
  `device_protection`, `tech_support`, `streaming_tv`, `streaming_movies`, `contract`,
  `paperless_billing`, `payment_method`.

`OneHotEncoder(handle_unknown="ignore")` means a category the model has never seen encodes
to all zeros rather than raising at inference time — important because the API accepts
free-form categorical values from clients.

## Reproducibility

- Every hyperparameter and the dataset path come from `ml/training/config.yml`, which is
  committed and logged to MLflow as run parameters.
- `random_state: 42` fixes both the split and the forest.
- `docker/training/Dockerfile` pins the Python version and library set, so a rerun on VM11
  months later produces the same model.
- Re-running `scripts/train-and-register.sh` (manually or on a CI/CD schedule) is the
  demonstration of the reproducible-training requirement.

## Promotion criteria

From `ml/training/config.yml`:

```yaml
evaluation:
  probability_threshold: 0.5
  max_f1_regression: 0.01
```

A new version may be promoted only if its F1 on the held-out test set is at least
`production_f1 - 0.01`. Anything worse fails the pipeline before the approval gate is even
offered. When there is no `Production` model yet (first ever run), evaluation passes
automatically.
